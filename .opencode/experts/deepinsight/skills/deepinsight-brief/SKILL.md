# deepinsight-brief（深度研究）

你（主agent）直接执行全流程，不派发任何子代理Task。一次会话产出完整深度研究报告与HTML/PDF。用户完整原话、必答问题、重点、篇幅、受众、格式、边界与禁止事项全程贯穿，不得中途丢失或弱化。

## 触发边界

| 用本技能 | 不用 |
|---|---|
| "做一个XX行业深度研究/调研报告" | "XX公司最近怎么样"（单点快问直接答） |
| "对比分析A与B"、"解读XX政策影响" | A股标的交易研究（deeptrading-report） |
| "XX技术趋势研判"，可带可不带材料 | 政企客户谈参高拜（zhengqi-brief） |

## 工作目录

如果会话提供了独立产物目录，以该目录作为运行目录，使用绝对路径读写报告产物，不另建工作区级目录。没有会话产物目录时，才在当前工作区根创建 `./deepinsight-runs/<yyyymmdd-主题短名>/`。全部产物落盘，不在对话囤积全文：

```
10-requirements.md    要求台账（第1步写，全程对照）
20-plan.md            研究计划（P0/P1问题、查询、路由）
30-evidence.md        证据卡片 + 引用编号表（写作前固定）
40-outline.md         章节蓝图（P0映射、字数分配）
50-report.md          报告正文（分章追加写入）
60-quick-report.md    渲染用正文（50加图表占位后复制）
61-quick-charts.json  图表配置
00-input.json         渲染元信息
65-quick-report.html  交付HTML
66-quick-report.pdf   交付PDF
```

## 全流程（顺序执行）

### 第1步 要求台账与消歧（读 references/requirements-ledger.md）
从用户原文逐项提取：必答问题、重点方向、篇幅（未指定时默认目标20000字）、受众、格式（引用样式默认[N]，用户要求`[SRC-01]`式时服从）、时间范围、地域范围、明确禁止事项，写入 `10-requirements.md`。主题存在歧义（电影/人物/公司/作品/同名机构）时最多2条消歧查询，只看前几条结果，**消歧结果不作报告证据**。无实质歧义直接进第2步。

### 第2步 研究规划（读 references/research-planning.md）
写 `20-plan.md`：研究问题分级（P0必答/P1重要/P2可选）、每个问题的查询方向、证据路由（有上传材料=internal或hybrid；纯公开=external）。用户必答问题全部入P0。规划不展示给用户确认，直接推进。

### 第3步 证据研究（读 references/evidence-discipline.md）
**本地材料**（有则必读）：上传材料是研究对象不是附件点缀——逐文件深读，围绕P0/P1问题提取证据，不被网络信息替代。
**公开研究**：按工具优先级执行——①`web-search`（远程搜索 MCP，工具名 `web-search_*`）②`mw_search_batch_collect_search_round`（任务包可用时）③`mobilework_search`（MobileWork宿主通道）④`websearch`/`webfetch`——**任一可用即执行**，全部不可用才只用本地材料如实说明。首选工具错配立即降级到下一个，不重试不放弃。首轮每问题1—2条查询并行覆盖全部维度；**第二轮只在三条件同时成立时执行**（存在影响P0结论的实质缺口 + 已明确1—3个未执行的互补新查询 + 预期获得新来源而非换词重搜），第二轮后必须收敛。
全部证据以卡片形式沉淀 `30-evidence.md`：事实表述+主体+时间+来源名+URL。来源冲突并列登记不裁决；搜索摘要没有的数字、条款、因果不补全。

### 第4步 引用编号表
证据准入完成后、写作开始前，在 `30-evidence.md` 头部固定引用编号表：`[1] 来源名（URL/文件名，时间）`连续编号。此后正文引用一律用该表，写作中不得重新编号或临时插入。

### 第5步 大纲（读 references/outline-writing.md）
写 `40-outline.md`：跨来源分析（回答了什么/冲突在哪/缺口是什么）、报告类型判定（行业综述/对比分析/政策解读/趋势研判/事件归因）、章节蓝图。**每个P0必须映射到具体章节**；章节字数之和等于目标字数；证据不足的确定性结论不进大纲。规划原生Markdown表格（真实可比数据才列）。

### 第6步 分批写作
目标≤6000字一次成文；更长报告按自然章节分批，每批≤6000字，**每写完一批立即落盘** `50-report.md` 再写下一批。写作依据=40-outline+30-evidence对应卡片+10-requirements，不在上下文重囤全部原始搜索结果。各批共享同一编号表、术语与大纲，不互相引用批次文本。正文关键事实与数据后标[N]；文末`## 参考文献`节按编号表全列（含未在正文引用但合规的来源），**每条必须是独立有序列表项：行首`N. `，条目单换行分隔**（裸`[N]`行会被渲染成一段）；最后一段免责声明：`本报告仅供研究参考，不构成任何投资或商业决策依据。`

### 第7步 自核验（读 references/review-checklist.md）
对照清单一次检查：标题结构与40-outline一致、P0全部有章节承载、引用样式与用户要求一致且[N]与编号表一一对应、关键数字可回溯证据卡片、无占位符残留、无编造的因果与预测。问题就地修复一次，不循环审稿。

### 第8步 渲染与交付
1. 复制 `50-report.md` 为 `60-quick-report.md`，在适合位置插入 `<!--CHART:xxx-id-->` 占位（一行独立成段）。图表数量积极取向：**每个数据密集章节至少评估1幅，全篇默认4—6幅**（引擎上限6幅），仅当全报告确实无可比数据才少于3幅并在交付时说明。
2. 写 `61-quick-charts.json`：`title` 与60首行H1逐字一致；`hero_stats` 留空数组（研究模板无顶部数据卡，不产出）；`charts`≤6，option直写但**数字只取正文真实数据**；每幅附`table`（列≥2、与图同源）。图表类型服务分析，且**同报告类型尽量不重复**（同型超过2幅时复查是否有更贴切形态）：

| 分析意图 | 推荐类型 |
|---|---|
| 时序趋势 | 折线（多系列）、面积（累计/占比演化） |
| 构成 | 堆叠柱、百分比堆叠（跨期构成）、饼/环形（≤5类） |
| 分组对比 | 分组柱（短标签）、**横向条形**（长标签/排名/档位） |
| 多维能力对比 | **雷达**（3—6维、2—4对象） |
| 性价比/两变量相关 | **散点**（x成本y效果）、气泡（加第三维） |
| 双指标联动 | **双Y轴组合**（柱+线，如消耗量与耗时） |
| 目标对照 | 条形+markLine（均值/目标线）、markPoint极值标注 |
| 单调递进（档位/阶梯） | 折线+markPoint（凸显跳变） |
3. 写 `00-input.json`：
```json
{
  "mode": "deepinsight",
  "template": "deepinsight",
  "current_date": "<今天YYYY-MM-DD>",
  "brand_kicker": "DEEPINSIGHT · 深度研究",
  "footer_text": "DeepInsight 深度研究",
  "source_heading": "## 参考文献",
  "disclaimer_text": "本报告仅供研究参考",
  "disclaimer_html": "免责声明：本报告基于公开信息与所提供材料整理，仅供研究参考，不构成任何投资或商业决策依据。数据口径以文中标注期间为准。"
}
```
4. 渲染（本技能自带引擎，无需其他技能）：
```
node <本技能安装路径>/render/render.mjs <run目录绝对路径>
```
路径定位：本项目内为 `.opencode/experts/deepinsight/skills/deepinsight-brief/render/render.mjs`（以 skill 工具返回的技能目录为准）。
校验失败按短码修正60/61后重跑（不改50正文）；PDF失败不阻塞HTML交付。最后交付50/60、HTML、PDF绝对路径与一句话状态。

## 红线（全程有效）

- 关键事实必须可追溯：主体、时间、数字、单位、政策、案例、重要观点引用已登记来源；材料/来源未说明的不补全，推断必须说明依据和边界
- 来源冲突并列呈现不裁决；证据不足宁可降级表达或明确局限，不硬下结论
- 用户材料只读不改；不得把用户原始输入缩成一句泛化主题
- 正文不出现机器编号之外的流程噪声（无SRC-XX内部标识、无"作为AI"、无自我保证）
- 上传材料与公开信息分层归属：材料事实不写成公开报道，公开数据不写成材料结论
