# 要求台账与主题消歧

## 台账字段（写入 10-requirements.md）

从用户原文逐项提取，未提及的标"未指定"并按默认处理：

```
# 研究要求台账
- 用户原话：<完整粘贴，不得缩写>
- 主题：<一句话>
- 必答问题：<逐条列出；没有则"未指定"，由主题推导P0>
- 重点方向：<用户强调的侧重>
- 篇幅：<用户字数要求；未指定默认目标20000字>
- 受众：<管理层/技术团队/内部参考；未指定默认内部研究参考>
- 引用样式：[N]（默认）/ [SRC-01]（用户明确要求时）
- 时间范围：<研究覆盖期；未指定默认近3年侧重近期>
- 地域/市场范围：<未指定默认中国为主、全球为辅>
- 格式与交付：<Markdown+HTML+PDF默认>
- 禁止事项：<用户明确不要的内容>
- 附件/材料：<路径清单；无则"无">
```

## 贯穿纪律

- 台账一旦写定，第2/5/6步开始前各对照一次：P0是否覆盖全部必答问题、大纲是否承载重点、正文是否遵守禁止事项
- 用户要求相互冲突时（如篇幅5000但必答问题极多），按"必答问题优先于篇幅"处理并在交付时说明
- 材料或大纲中发现的新增重要维度可补充进台账并标注"研究补充"，但不覆盖用户原始要求

## 主题消歧（可选）

仅当主题可能指代多个截然不同对象时执行（同名公司/人物与作品/机构与地名）：

- 最多2条查询，每条只看前2—3条结果
- 消歧只确定"研究对象是什么"，**消歧来源不进入报告证据与参考文献**
- 消歧后把锁定对象写进台账"主题"字段；无法锁定且对象差异实质影响结果时，用一次提问向用户确认
