# 通用 Playbook 工作指引

本 playbook 服务于 `DeepTrading 多股对比中心`。所有 agent（团长 + 团员）在执行任务时均须遵守以下通用规范。

## 团队概览

本专家团按蜂群流程编排多股横向对比：聚合输入报告 → 多维度交叉对比 → 七章对比总报告 → 多股横评可视化看板。采用两层 subagent 架构（L1 团长 + L2 专家），不依赖任何外部数据源，但需要 Python 3 运行时（团长编排用的后处理脚本，跨平台）。

## 编码规范（跨平台）

- 所有 workspace 文件（`.md`、`.html`、`.json`）使用 **UTF-8（无 BOM）** 编码写入。
- 后处理脚本为 `.opencode/scripts/` 下的 Python 3 脚本，读写时显式指定编码（读取用 `utf-8-sig`，兼容历史 BOM 文件），无需任何 BOM 处理。
- 运行方式：`python3 <script>`；Windows 上若无 `python3` 命令则用 `python`。

## 免责声明（硬性）

所有报告末尾必须保留"**本报告不构成投资建议**"字样。不承诺收益、不给出实盘交易指令语气（"建议买入/卖出"），但必须给出**明确方向性观点**（优先配置/持有/降低权重/回避）。

## 数据完整性（核心）

- **不编造**：所有事实和数据必须来自输入的个股报告。报告中没有的数据标注"报告未提及"或"数据缺失"
- **不新增外部数据**：对比分析**不联网搜索**、**不调用外部工具**，完全基于输入报告内容
- **口径一致**：对比时确保各标的数据口径一致（同为 TTM、同为年报），不一致时注明
- **保留引用**：原报告中的 `[N]` 引用编号原样保留

## 输出纪律

- **第一行**必须是指定格式的标题
- **严禁**寒暄："好的"、"收到"、"作为XX专家"、"我将综合"、"下面是"
- **严禁**任何元叙述
- 除标题/小标题/正文/表格外，不输出任何说明性包装文本

## workspace 约定

```
tmp/comparison-workspace/<run-id>/
  00-input.json              # 用户原始输入与配置
  01-sources.json            # 标准化报告列表（含全文 content）
  10-comparison-matrix.md    # 多维度交叉对比矩阵
  20-comparison-report.md    # 七章对比总报告
  30-visual-report.json      # 横评可视化 JSON
  40-comparison-report.html  # HTML 对比看板
  50-stats.json              # 统计信息
```

## 容错策略

- 某 L2 专家失败 → 编排代理重试 1 次，连续 2 次失败则终止流程并报告 workspace 路径
- JSON 解析失败 → 去掉 markdown 代码块包裹再解析
- 可视化 JSON 失败 → 降级为单 section + 单 markdown block
- HTML 渲染失败 → 不阻塞 markdown 报告交付

## 交付契约

回传：任务理解、标的列表、生成/更新的文件名、核心结论、验收状态与剩余风险。
