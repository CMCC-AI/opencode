# 财报后反应（earnings-review）

> **何时加载**：事件影响（event_impact）中财报/业绩会子场景："财报怎么样 / 业绩会说了啥 / 为什么超预期但不涨 / 财后怎么看"。
>
> **契约关系**：支撑 60 的"事件事实与时间线 / 市场已定价程度 / 后续观察点"章节。

## 核心目标

**同时解释"财报内容"和"市场反应"**——结果好坏是一回事，股价反应强弱是另一回事。

## 分析步骤

1. **确认事实与价格反应窗口**：财报披露日期与时点（盘前/盘后）、股价在披露前后各窗口的反应（披露日 / 次日 / 一周）、反应幅度是否超出历史常态、同板块可比是否联动。价格还在快速变化时声明"判断仅代表当前时点"。
2. **拆开"结果"与"表现"**：
   - 收入 / 利润 / 利润率 / 现金流核心结果是否超预期
   - 经营指标是否支持
   - 指引是否上修 / 持平 / 转弱
   - 增长质量是来自主业 / 结构优化 / 还是一次性
   - 价格反应是放大财报结论还是与财报错位
3. **识别市场真正交易的核心分歧**：增长可持续性 / 利润率触顶或修复 / 某业务线是否进入拐点 / 管理层指引是否反映更深层问题 / 原本定价的故事是否被强化或削弱。**若股价与 headline 相反，重点解释市场为何忽略表面利好**。
4. **业绩会/说明会提炼**：管理层措辞变化（去年的"强劲增长"今年变成"稳健增长"）、问答环节的市场分歧定位、新增信息 vs 重复口径、是否有指引上下调。
5. **判断财报后持续性**：反应是一次性情绪释放还是趋势级重估起点、哪些细节会在次日 / 次周继续交易、若市场解读过度后续如何回摆。
6. **更新研究判断**：原有投资逻辑被强化 / 削弱 / 基本未变、若继续跟踪下一步最值得验证什么。

## 取数（本包数据源）

- 财报数字：`akshare_get_income_statement / get_cashflow / get_balance_sheet`（curr_date 对齐到披露日后）+ `akshare_get_fundamentals` 摘要
- 披露事件与原文：`akshare_get_company_announcements`（定期报告公告 URL）
- 价格反应窗口：`akshare_get_stock_data`（披露日前后各 10-15 个交易日日线，算窗口涨跌）
- 业绩会/媒体解读：360 智搜（"X 业绩会 2026"）；非一手解读标"需核实原文"

## 避坑

- 同时解释财报内容 + 市场反应，不能只写一半
- 股价与 headline 不一致时，优先解释错位原因
- 不能把所有变动归因为单一指标，要突出**真正决定反应的主变量**
- 盘后情绪当长期结论是常见错误——带时间窗口意识
- 财后漂移（PEAD）是真实存在的：超预期后的趋势可能延续 1-3 个月，不要把首日反应当全部
- 业绩会措辞是"解读的解读"——引用时标注来自媒体转述（非一手）
