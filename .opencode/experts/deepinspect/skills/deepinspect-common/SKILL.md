# AI+巡查 通用工作规范

本规范服务于 `AI+巡查`。所有成员（主理人 + 十一位团员）在执行任务时均须遵守以下通用规范。

## 团队概览

本专家团按 9 阶段 SOP 编排巡查任务：意图分析 → 研究方案规划 → 材料研究（含风险识别）→ 问题归并 → 反思评估 → 大纲生成 → 报告撰写 → 证据核验 → 可视化增强。采用 Team 型协作架构（团长调度 + 团员独立执行），在反思和核验节点进行质量门控。

## 事实边界（核心纪律）

1. **材料是事实主体**：所有发现必须来自用户上传的材料
2. **不编造**：材料没有写明的数据留空或标记"材料未说明"
3. **不简化**：具体事实完整保留，不做摘要式删减
4. **可追溯**：每项事实关联来源文件编号（SRC-*）
5. **冲突保留**：分别保留不一致表述，不自行裁决

## 编码规范

所有 workspace 文件（`.md`、`.json`）使用 **UTF-8** 编码写入。

## 引用格式

- 本地材料事实使用 `[SRC-001]` 格式标注来源文件编号
- `SRC-*` 必须来自 `04-sources.json` 来源注册表
- 同一句话最多 2 个引用标注
- 外部搜索事实使用真实 URL

## 质控原则

1. **采集时质控**：web-researcher 对搜索来源做可信度分层（政府/学术/官方权威优先，内容农场/SEO 堆砌剔除）
2. **采集后质控**：reflector 评估步骤覆盖度 + evidence-reviewer 独立核验事实与来源
3. **统计准确性**：`statistics.total_risks` 必须等于 `risks` 数组长度；各分类统计之和必须等于总数

## 容错策略

- 某团员失败 → 主理人写占位说明，后续环节继续，不中止全流程
- 工具调用失败或超时 → 记录错误说明，交回主理人
- 主理人对每个阶段产出做抽查，失败重试 1 次
- 整体最大尝试次数：每位团员最多重试 2 次

## 输出纪律

- **第一行**必须是指定格式的标题（各团员有各自约定）
- **严禁**寒暄："好的"、"收到"、"作为XX专家"、"我将综合"、"下面是"
- **严禁**任何元叙述："我将采用SCQA逻辑"、"本节将达到"
- 除标题/小标题/正文/表格外，不输出任何说明性包装文本
- 团长调度指令和团员回传消息不受上述限制（那是协作通信，不是最终报告内容）

## 内部标签隔离

- `COMMON-001`、`R001`、`CONFLICT-001` 等内部追踪键严禁出现在正式报告中
- `group_id`、`risk_id`、`conflict_id`、`source_ids`、`risk_level`、`confidence` 等字段名不得外泄
- 材料中真实存在的英文缩写（如 PPE、HSE、5S、ICT、DICT）可以保留

## 数据完整性

- **不编造**：所有事实带来源编号；无法确认时写"材料未说明"或"待人工复核"
- 数值冲突时保留每个版本及来源，不自动选定唯一版本
- 每条事实后必须有来源标注

## 交付契约

每位团员回传时须包含：
1. 任务理解（接收到的分析任务概述）
2. 调用的工具与关键入参
3. 生成/更新的文件名或内容
4. 核心结论（不超过 3 句话）
5. 数据缺口（哪些维度的数据缺失）
6. 验收状态与剩余风险

失败或阻塞时列出缺失输入、原因与补救建议。
