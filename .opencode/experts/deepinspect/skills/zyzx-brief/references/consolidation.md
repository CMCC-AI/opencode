# 问题归并与共性研判（第4步，needs_consolidation=true 时执行）

用问题台账建立跨材料关系，识别共性、保留个性、去重并评估材料覆盖。**不重写原文事实**：共性组只引用 ISSUE 编号，完整事实留在 20-issues-ledger.md。产出写入 `30-consolidation.md`。

## 归并判据（同主题不等于共性）

- **相同制度薄弱点、行为表现或共同内核**才归并；仅在标题或领域上相似不算
- 跨单位共性：至少 **2 个独立单位**的证据
- 单位内共性：至少 **2 个独立业务条线**的事实
- 两个文件重复记录同一事项不是两个独立问题（见去重）
- 单单位不能因为来源多直接形成共性

## 共性组格式

```
## 共性组 G1 <共同内核标题>
- 范围：cross_unit（跨单位）/ within_unit（单位内跨条线）
- 成员：ISSUE-001（XX县分公司）、ISSUE-004（YY事业部）、ISSUE-009（ZZ中心）
- 归并理由：<为什么这是同一内核，不是同主题；一句内核+机制成因即可>
- 差异：<各成员事实之间的真实差异，可选>
- 边界：<推断边界、材料未覆盖处>
- 典型标注：<可选，附典型成员 ISSUE 编号；典型是附加标签，可与共性/个性重叠>
```

**研判不双写**：本文件只登记上述字段，"综合研判"完整段落（共性表现→机制成因→影响风险）**留到第6步正文按公文段落体一次写**，不在归并阶段预写、正文再改写一遍。

## 去重判定

- 判定重复必须给理由；原始记录仍留在台账（不物理删除）
- **整改更新、主体不同、金额不同不能当作重复**；真正的重复记载标注"与 ISSUE-XXX 同一事实，正文引用其一"

## 计数纪律（统计红线，写作与图表全程有效）

- 问题数量按**去重后的原子事项**计算
- 共性、个性、典型标签**不是互斥总量，不相加**
- 不重复计数、不自动合计金额（不同单位/期间/口径的金额不直接相加）、不虚构比例
- context/measure/suggestion 类记录可组织引用，但不混进问题计数

## 覆盖对照（写入 30-consolidation.md 末节）

对照 10-requirements 逐条标注：已覆盖 / 缺材料 / 读取失败。缺材料不发起重新研究循环，重要未知留给正文明确说明。

## 表述边界（写作阶段继续有效）

- 未成立共性组的事项，正文**不得声称"普遍存在"**
- 归并失败时逐项保留为独立问题，不强行归并
- 分类首先服从用户要求
