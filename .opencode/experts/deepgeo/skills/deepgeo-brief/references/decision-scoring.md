# 评分与决策纪律

综合评分是把各领域已算出的指标组合成排序的过程。纪律的核心：**透明、可复算、不为期待排序反调**。

## 1. 默认七维度

客流潜力、目标客群、可达性、业态协同、竞争压力、经营成本、财务回报。

任一维度因数据不足或证据降级未进入评分时：**必须声明排除原因与对排序的可能影响，不得静默省略**。可达性数据缺失时不得用直线距离冒充交通方式与时间成本。

## 2. 评分流程（全部走 CLI，不手算）

1. 从各领域 `20-analysis` 结果中摘原始指标（每指标登记：来源配方、口径、单位、样本）；
2. 给每个指标定方向（越大越好 / 越小越好），向用户展示后再进入计算；
3. `decision.score`：标准化 + 加权 + 总分 + 排名（params 传指标矩阵、方向、权重）；
4. `decision.stability`：权重扰动下的排名频率——排名不稳的候选必须写进结论("A 与 B 在合理权重范围内互有胜负")，不得硬分高下；
5. 一票否决项单独列：面积不足、租期过短、营业时段受限、可达性极差等硬伤直接出局，不进加权。

## 3. 权重档位

| 档位 | 适用 |
|---|---|
| **均衡推荐（默认）** | 通用 |
| 客流优先 | 走量型业态 |
| 客群匹配优先 | 目标客群敏感业态（体验/亲子/潮流） |
| 成本保守 | 资金紧张/新品牌首店 |

默认用均衡推荐档；用户显式换档时记录"档位+理由"，写入 30-model.md；**禁止为得到理想排序反向切换档位**。

## 4. 财务边界（选址型）

- `finance.scenario`：保守/基准/乐观三情景的月收入、经营利润、**盈亏平衡客流**；
- `finance.monte_carlo`：亏损概率、利润分位数——报告写成"把票价、上座率、成本在合理范围内随机组合一万次，这个点位有多少次会亏损"；
- 静态回收期可用确定性输出；**NPV/IRR 未实现：报告中明确标"未计算"，不得手算补齐**。

## 5. 预测纪律

- 只在当日级连续历史数据足够且会改变决策时启用 `forecast.baseline`；
- 三基线（近期平均/同星期/直线趋势）先留出最近一段回测，选误差更小者；
- 输出必须是**范围 + 方向 + 回测误差 + 失效条件**（节假日/天气/活动/竞争变化），不写单点承诺；
- 表达模板："按当前规律推演，未来 4—8 周 X 点位周均有效停留预计在 A—B 人次区间；若周边竞品开业或商场活动节奏变化，该推演失效。"

## 6. 产出（30-model.md）

一个文件收纳：维度表（含排除声明）、原始指标、方向、权重档位、标准化得分、总分排名、稳定性结论、一票否决、财务情景与亏损概率、预测范围。图表与正文只引用此文件已登记的数字。
