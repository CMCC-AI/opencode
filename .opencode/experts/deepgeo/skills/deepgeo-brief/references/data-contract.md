# 数据契约与质量

你负责把用户给的数据目录变成"可分析、可追溯、边界清晰"的准入状态。分析只允许在准入后的表上进行。

## 1. 首次读取（读一次，不全量倒进对话）

1. 列出数据目录全部文件（含子目录）；
2. 优先读元数据：`case.json`（brief/data_dictionary）、`CASE.md`、README——登记决策请求、必覆盖项、数据模式声明、表说明；
3. 逐表只采样前 3—5 行确认结构（列名/主键/时间粒度/单位/质量标志列），全量统计交给 `quality.profile`，不在对话中逐行肉眼扫描；
4. **不复制原始数据**；确需中间转换（过滤/拼接/单位换算）时写入 `.scratch/`，并在正式产物里记录哈希与口径。

## 2. 数据契约（写入 10-data-contract.md）

每张准入的表登记一行：

| 表 | 业务含义 | 主键/对象 | 时间粒度 | 关键单位 | 质量标志列 | data_mode |
|---|---|---|---|---|---|---|

配套记录：空间口径（网格/点位/分区）、时间范围、对象范围（几个点位/网格/商铺）、血缘（结论用了哪些表的哪些列）。

## 3. 质量画像（用确定性计算，不目测）

对每张进入分析的核心表跑一次：

```
python -m analytics.deepgeo.cli run --recipe quality.profile --input <表.csv> --producer deepgeo-brief --output .scratch/quality-<表名>.json
```

关注：行列规模、空值模式、唯一性、数值范围、时间断点、质量标志列分布（ok/异常/缺失）。

## 4. data_mode 三态（贯穿一切产物）

- `simulated` / `real` / `mixed`：由 case.json 声明或数据列明示，**不得由文件名或直觉猜测**；
- 每个 JSON 结果、每张图、报告标题区与免责声明都要携带；
- 模拟数据不得被描述为真实客户事实或真实经营效果；图面必须显示"模拟数据，仅用于演示"。

## 5. 质量结论（四选一，写进 10-data-contract.md 首部）

| 结论 | 含义 | 动作 |
|---|---|---|
| proceed | 核心表完整可用 | 继续全流程 |
| degrade | 有缺口但可降级分析 | 列出：降掉了什么、哪些结论因此**禁止**下 |
| request_data | 缺关键数据 | 列清缺哪张表哪个字段，向用户要，或按已有数据缩小问题 |
| stop | 数据根本不支持该决策 | 如实告知，不出报告 |

## 6. 数据处理红线

- 缺失不自动填零；
- 不为结论好看删异常——活动、天气、闭店、采集断点分开处理（`temporal.anomaly` 的异常标记用于隔离而非删除）；
- 单位与口径原样保留，换算必须记录在契约里；
- 敏感边界：只处理聚合数据；若发现疑似个人轨迹级数据，停止并说明，不继续分析。
