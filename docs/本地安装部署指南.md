# APP-CMCC 本地安装、部署与测试指南

本文统一整理 `cmcc-local-dev` 的 macOS 和 Windows 安装流程，适用于 `research-quota-demo` 科研限额演示分支。配置与命令依据现有 `dev.sh`、`scripts/dev.py`、`dev.ps1` 和 `.env.example` 核对，整理日期为 2026-10-08。

## 1. 组成与目录

本地使用 Docker 运行 MySQL、Redis，使用宿主机进程运行 OpenCode、DockAPI 和 APP-CMCC。DeepXiv 由前端启动同站代理，论文服务本身不包含在本地一键启动中。

三个仓库必须同级，目录名应保持如下结构：

```text
ai-agents/
├── cmcc-local-dev/          一键启动、Compose、配置与日志
├── dockapi-service/         登录、用户与业务会话
└── opencode/               模型调用、额度与前端
    └── packages/app-cmcc/
```

从团队仓库获取这三个项目。OpenCode 和 DockAPI 的演示版本使用 `research-quota-demo`；`cmcc-local-dev` 使用与之匹配的版本。现有代码先确认工作区状态再切换分支，启动脚本不会自动拉取代码或切换业务仓库分支。

后文除明确标注外，命令均在 `cmcc-local-dev` 目录执行。OpenCode 根目录的 `bun dev:web` 启动的是另一套 `packages/app`，本演示应使用联动脚本启动 `packages/app-cmcc`。

## 2. 宿主机软件

| 软件 | macOS | Windows |
| --- | --- | --- |
| Git | 可在终端使用 | 可在终端使用 |
| Docker Desktop | Engine 已启动，支持 Compose v2 | Engine 已启动，支持 Compose v2 |
| Bun | 与 `opencode/package.json` 一致，当前 1.3.14 | 现有脚本检查 1.3.14 |
| Java | JDK 17 或以上，包含 `javac` | 按现有脚本准备 JDK 17 |
| Maven | `mvn` 可用，使用有效 JDK | 建议 3.9.x，`mvn -version` 显示 Java 17 |
| Python | 3.9 或以上，无需 pip 依赖 | PowerShell 工作流不需要 |
| PowerShell | 不需要 | 7.x，命令为 `pwsh` |

macOS 缺少 Java 或 Maven 时可使用 Homebrew：

```bash
brew install openjdk@17 maven
# 仅在缺少 Python 3.9+ 时执行
brew install python
open -a Docker
```

Docker Desktop 未安装时，按电脑芯片选择安装包。安装软件后重新打开终端；脚本不会自动安装系统工具。

macOS 脚本优先使用显式 `JAVA_HOME`，否则尝试系统 JDK 17 和常见 Homebrew JDK 17 路径，仅为子进程调整环境，不修改系统 Java 配置。需要指定 JDK 时：

```bash
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
java -version
mvn -version
```

Windows 若 Maven 使用了错误 Java 版本，在 PowerShell 7 中配置：

```powershell
$env:JAVA_HOME = 'C:\实际的JDK17目录'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn -version
```

## 3. macOS 首次安装与启动

```bash
cd /你的路径/ai-agents/cmcc-local-dev
./dev.sh doctor
./dev.sh bootstrap
./dev.sh alibaba-env
./dev.sh up
./dev.sh smoke
```

`doctor` 检查仓库、工具链、Docker 和端口配置。`bootstrap` 启动基础设施、补建缺失表、准备模型快照、执行 `bun install --frozen-lockfile` 和 DockAPI Maven 编译。锁文件不一致时会失败，不会自动更新锁文件。

`alibaba-env` 在交互式终端中接收 DashScope API Key，不回显输入，将其保存到 Git 忽略的 `.env`。科研演示启动需要部署方提供 `DASHSCOPE_API_KEY`；已有有效配置时可跳过输入。用户前端仅选择后台配置的模型。

`up` 检查端口、启动基础设施与应用，并等待健康响应。已健康运行的托管进程会复用。修改环境配置后，应先 `down` 再 `up`。

默认浏览器地址是 `http://localhost:3000/`。当前这台开发机的 `.env` 配置了 `LOCALDEV_APP_PORT=3001`，实际地址是 `http://localhost:3001/`；以 `up` 输出和 `status` 为准。

## 4. Windows 首次安装与启动

打开 PowerShell 7，进入同级的 `cmcc-local-dev`：

```powershell
Set-Location C:\你的路径\ai-agents\cmcc-local-dev
./dev.cmd doctor
./dev.cmd bootstrap
./dev.cmd alibaba-env
./dev.cmd up
./dev.cmd smoke
```

也可使用 `pwsh ./dev.ps1 doctor` 等等价命令。现有 Windows 入口的应用端口固定为 OpenCode `4096`、DockAPI `8081`、APP `3000`；不要照搬 macOS 应用端口覆盖配置。

Windows 入口保留旧 PowerShell 工作流，和 macOS 的配置注入、数据库位置、进程管理并不完全一致。它没有自动注入 macOS 入口的默认科研开关及额度策略。测试科研限额时，启动前在本地 `.env` 显式设置：

```dotenv
VITE_CMCC_RESEARCH_DEMO=true
OPENCODE_CMCC_RESEARCH_DEMO=true
OPENCODE_TOKEN_QUOTA={"enabled":true,"identityHeader":"x-opencode-user-id","authorizationHeader":"x-dockapi-authorization","identityUrl":"http://127.0.0.1:8081","monthlyTokens":10000000,"reservationTokens":8192,"overage":"reject"}
VITE_DOCKAPI_URL=http://127.0.0.1:8081
```

Windows 的 `bootstrap` 使用 `bun install`，不同于 macOS 的 frozen-lockfile 模式。Windows 入口会清除 `OPENCODE_SERVER_PASSWORD`，不要把它作为生产鉴权方案使用。本文核对了 Windows 脚本，但本次没有执行 Windows 实机验收。

## 5. 配置与端口

本地配置放在 `cmcc-local-dev/.env`。首次需要覆盖默认值时复制 `.env.example`；已有 `.env` 时不要覆盖。文件使用字面值 `KEY=VALUE`，支持一对外围引号，不使用 shell 表达式、变量插值或行尾注释，也不要用 `source .env` 加载。终端已导出的同名变量优先于文件。

供同事转发的完整配置模板见 [local-dev.env.example](config/local-dev.env.example)。将内容保存为同级 `cmcc-local-dev/.env`，替换 API Key；不要放到 `opencode/.env` 或 `packages/app-cmcc/.env`。模板采用当前 Mac 的前端 `3001` 端口；Windows 入口仍固定使用 `3000`。JWT/SSO 密钥在 macOS 下可自动生成，只有需要配套 DeepLiterature SSO 时才需明确同步服务端 SSO 密钥。

| 配置项 | 默认值 | 支持范围 |
| --- | --- | --- |
| `LOCALDEV_MYSQL_PORT` | 3306 | macOS / Windows |
| `LOCALDEV_REDIS_PORT` | 6379 | macOS / Windows |
| `LOCALDEV_OPENCODE_PORT` | 4096 | macOS |
| `LOCALDEV_DOCKAPI_PORT` | 8081 | macOS |
| `LOCALDEV_APP_PORT` | 3000 | macOS，当前开发机为 3001 |
| `LOCALDEV_DEEPXIV_PORT` | 3100 | macOS |
| `DOCKAPI_DB_PASSWORD` | 本地开发默认密码 | macOS / Windows |
| `DOCKAPI_DB_ROOT_PASSWORD` | 本地开发默认密码 | Docker 初始化 |
| `DASHSCOPE_API_KEY` | 部署方填写 | 百炼模型凭据 |
| `MODELS_DEV_API_JSON` | 可选已有模型快照路径 | 离线模型目录 |
| `DEEPLIT_PROXY_TARGET` | `http://81.70.174.140:3000/` | DeepXiv 代理上游 |

macOS 六个端口必须互不重复，脚本会同步更新 JDBC、Redis、前后端地址及 CORS。应用绑定回环地址，Vite 使用严格端口模式，不会自动换端口。避开本机已有数据库的示例：

```dotenv
LOCALDEV_MYSQL_PORT=13306
LOCALDEV_APP_PORT=3001
```

macOS 其他可选配置：

- `JAVA_HOME`：显式指定 JDK 路径。
- `LOCALDEV_MAVEN_SETTINGS`：本项目 Maven settings XML 路径，相对路径从启动工具目录解析。
- `OPENCODE_DB`：指定 SQLite 文件；复用已有库前先备份并确认没有其他实例并发使用。
- `DOCKAPI_JWT_SECRET`：覆盖本地生成的 JWT 密钥。
- `DOCKAPI_SSO_CLIENT_SECRET`：覆盖本地生成的 SSO 客户端密钥。
- `OPENCODE_SERVER_PASSWORD`：本地 Basic Auth，会同步传给 DockAPI、前端与健康检查；前端配置对浏览器可见。

真实密钥不写入 Git、模型配置 JSON 或前端 `VITE_*` 变量。macOS `DASHSCOPE_API_KEY` 仅传给 OpenCode，`.env` 以 `600` 权限保存。

## 6. 模型与用户额度

科研演示使用中国区百炼 Provider `alibaba-cn`，隐藏国际站 `alibaba`。模型目录只是元数据，可选择的模型还取决于后台凭据和模型开通情况。遇到缺少 API Key 提示，检查启动进程是否加载管理员配置的 Key，再通过 `down` / `up` 重启。

macOS 入口默认打开 `VITE_CMCC_RESEARCH_DEMO` 和 `OPENCODE_CMCC_RESEARCH_DEMO`，界面保留主会话、科研专家团和 DeepXiv。默认每位登录用户每月 1000 万 Token，不设置每日和单次硬上限，超额拒绝调用。

额度通过 DockAPI 校验的用户身份绑定；共享模型 Key 不意味着共享用户额度。`reservationTokens=8192` 是请求前的额度预占参数，不是单次 Token 上限。用量可能包含系统提示、历史对话和工具上下文，不能仅按用户输入文字长度判断。

`OPENCODE_TOKEN_QUOTA` 可整体覆盖默认策略；手工覆盖且调整 DockAPI 端口时，同时更新 JSON 中的 `identityUrl`。实现细节见 [Token 限额设计](cmcc-token-quota.md) 和 [科研演示说明](cmcc-research-quota-demo.md)。

## 7. DeepXiv 与统一登录

本地 `up` 默认启动 `3100` 代理，上游为外部 DeepLiterature。代理端口就绪不代表上游可访问，也不代表已完成统一登录。当前服务器新实例的 `3004` 仅放行演示 APP 服务器，本地电脑不能直接将代理切换到该端口使用。

完整本地 SSO 需要配套的 DeepLiterature DockAPI 认证版本，并执行其对应迁移。在本地或为本地提供的独立 DeepLiterature Web 实例上配置：

```dotenv
DEEPLIT_AUTH_MODE=dockapi
DEEPLIT_DOCKAPI_URL=http://本机可达地址:8081
DEEPLIT_PUBLIC_ORIGIN=http://localhost:3100
DEEPLIT_PARENT_ORIGIN=http://localhost:3001
DEEPLIT_SSO_CLIENT_SECRET=与本地DockAPI一致的服务端密钥
```

上例以当前开发机 APP `3001` 为例；默认端口部署应改为 `3000`。容器内的 `127.0.0.1` 指容器自身，在 Docker Desktop 中需使用可达的宿主机地址并确认监听条件；远程 DeepLiterature 不能回调仅绑定回环的本机 DockAPI。浏览器统一使用相同主机名，避免 `localhost` 与 `127.0.0.1` 混用导致 Cookie/Origin 校验不一致。

`VITE_DEEPXIV_URL` 显式指定 iframe 地址时，会停用默认本地代理；只有配套入口已正确配置时才使用。不要为了本地联调直接覆盖现有服务器实例的 SSO 配置。完整协议和服务器双环境说明见 [DeepXiv SSO](../packages/app-cmcc/docs/deepxiv-sso.md)。

## 8. 日常操作与验证

| 操作 | macOS | Windows |
| --- | --- | --- |
| 启动 | `./dev.sh up` | `./dev.cmd up` |
| 状态 | `./dev.sh status` | `./dev.cmd status` |
| 日志 | `./dev.sh logs` | `./dev.cmd logs` |
| 基础冒烟 | `./dev.sh smoke` | `./dev.cmd smoke` |
| 测试并保留服务 | `./dev.sh test` | `./dev.cmd test` |
| 含类型检查 | `./dev.sh test --full` | `pwsh ./dev.ps1 test -Full` |
| 仅测试，不启动 | `./dev.sh test --unit` | 当前入口无等价开关 |
| 仅测试含类型检查 | `./dev.sh test --unit --full` | 当前入口无等价开关 |
| 停止并保留数据 | `./dev.sh down` | `./dev.cmd down` |

基础冒烟检查数据库/Redis、应用健康响应和本地连通性。macOS 还检查必需表、托管进程以及默认代理端口。它不请求真实模型，不自动注册用户，也不验证额度耗尽或 DeepXiv 上游业务。

部署验收应手工执行：注册和登录 → 查看个人额度 → 选择已部署模型 → 主对话流式响应 → 科研专家团 → 刷新后恢复历史 → DeepXiv 登录态。使用两个测试用户检查历史与额度隔离；验证超额流程时使用独立测试环境或测试用户策略。

OpenCode 不允许从仓库根目录执行测试。手工验证时进入对应包，类型检查使用 `bun typecheck`。启动工具自身的回归测试可在 `cmcc-local-dev` 执行：

```bash
python3 -m unittest discover -s tests -v
```

## 9. 数据、日志与权限

| 数据 | macOS 默认位置 |
| --- | --- |
| MySQL、Redis | `cmcc-local-dev` Compose named volumes |
| OpenCode SQLite | `cmcc-local-dev/.data/opencode.db` |
| JWT / SSO 随机密钥 | `.data/dockapi-jwt-secret`、`.data/dockapi-sso-client-secret` |
| 用户目录与产物 | `opencode/data/workspaces/` |
| 案例文件 | `opencode/data/cases/` |
| 模型目录缓存 | `cmcc-local-dev/.cache/models-dev-api.json` |
| 托管进程状态 | `cmcc-local-dev/.state/macos/` |
| 应用日志 | `cmcc-local-dev/logs/macos/` |

Windows 状态、日志位于 `.state/` 和 `logs/`，现有入口使用 `OPENCODE_CHANNEL=prod`，没有自动指定 macOS 的项目 SQLite 文件；需要结合实际运行配置定位数据库，不能直接假定两平台共用同一位置。

macOS supervisor 校验进程身份并管理子进程组。正常使用 `down` 停止；不要在运行时删除状态文件。外部强杀 supervisor 后应结合日志和端口占用手工核查。

本地应用以当前开发者账号运行，不需要创建 Linux `opencode` 服务用户，也不需要改变原项目目录归属。服务器的 systemd 用户及 `/srv/opencode` 归属属于生产部署配置，不应照搬到本地目录。

`down` 保留数据卷、SQLite 和产物。备份应覆盖 MySQL、Redis、SQLite、用户文件及密钥配置；只复制 MySQL 会留下无法对应的历史会话绑定。更换 JWT 密钥会使旧登录令牌失效。

## 10. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| Docker 命令存在但启动失败 | 打开 Docker Desktop，等待 Engine 就绪，再运行 `doctor` |
| Java / Maven 检查失败 | 检查 `JAVA_HOME`、`javac` 和 `mvn -version`，终端变量优先于 `.env` |
| 首次依赖下载失败 | 查看 Bun/Maven 网络或镜像设置；macOS 可使用 `LOCALDEV_MAVEN_SETTINGS` |
| 模型目录下载失败 | 用 `MODELS_DEV_API_JSON` 指向团队提供的有效 JSON，再运行 `bootstrap` |
| 模型提示缺少 Key | 使用 `alibaba-env` 配置，再 `down` / `up`；不要让普通用户自行填写 Key |
| 配置变更未生效 | 已有健康进程会复用；重启托管应用，并排查同名终端环境变量 |
| 修改数据库密码后无法连接 | 初始化密码仅对新卷生效；已有数据库需正常变更账号密码 |
| 升级后缺字段 | 表初始化只补建缺失表，不升级已有表；执行对应版本迁移 |
| DockAPI 仍读取旧 Windows 路径 | 使用联动入口，直接运行 Maven 不会自动得到路径覆盖 |
| 历史会话或产物无法打开 | 核对 MySQL 业务绑定、SQLite 和 workspace 路径；跨系统绝对路径需要迁移 |
| DeepXiv 代理正常但登录失败 | 检查上游可达性、父/iframe Origin、回调地址、共享密钥和认证版本 |

端口冲突时确认占用者，不要直接按端口批量杀进程：

```bash
# macOS：按实际配置替换端口
lsof -nP -iTCP:3001 -sTCP:LISTEN
```

```powershell
# Windows
Get-NetTCPConnection -State Listen |
  Where-Object LocalPort -in 3000,3100,3306,4096,6379,8081
```

查看数据库容器日志：

```sh
docker compose -f compose.yaml logs --tail 100
```

本工具没有自动重置命令。`docker compose down -v` 会删除数据库卷，不能用于普通停止或常规排障。Linux 可参考 POSIX 入口，但本文没有给出 Linux 实机验证结论。
