# 独立股票分析与策略回测产品方案

## 产品定位

`packages/app-stock` 是一个完全独立的股票策略研究产品，不属于 `app-cmcc`，也不接入 DeepTrading 专家团队或既有投研流程。产品面向希望验证个人投资规则的用户，用结构化表单完成严谨回测，用 AI 对话解释结果并协助设计下一轮实验。

产品吸收财经 AI 的通用优点：用户可以直接问自然语言问题；每个回答携带当前股票和策略上下文；指标、交易记录和数据口径可追溯；专业术语尽量用通俗语言解释。它不复制任何第三方页面或品牌形态。

## 目标用户与核心任务

第一阶段面向有明确投资规则、但不一定具备量化开发能力的个人研究者。核心任务链为：用自然语言或表单描述策略 → 选择市场和回测区间 → 明确交易成本 → 查看结果和可行性证据 → 用 AI 追问风险 → 调整参数并再次验证。

产品首先解决“规则在历史上是否值得继续研究”，而不是回答“现在应该买哪只股票”。任何可行性结论都必须同时展示样本、收益、风险、交易次数、基准和参数稳定性，不输出确定性的买卖承诺。

## 产品边界与统一入口

- `app-stock` 保持独立 package、独立前端、独立 API、独立发布能力和独立数据配置。
- `app-cmcc` 只增加登录后的导航入口和持久化页面容器，不把股票业务代码合并进现有流程。
- 开发环境由 `bun run dev:cmcc-stock` 同时启动两个产品；生产环境通过登录网关将股票产品映射到受保护的同域地址。
- 股票产品也可独立访问，便于单独开发、测试和未来拆分部署；是否开放独立公网入口由部署层决定。
- DeepTrading、DeepXiv 等现有产品和工作流不作为依赖，也不因本次接入而改变。

## 已实现架构

```text
packages/app-stock（独立产品）
  ├─ SolidJS 前端
  │   ├─ 策略参数与交易成本
  │   ├─ 回测指标、净值曲线、成交记录
  │   └─ AI 连续问答
  └─ Bun 服务端
      ├─ /api/backtest → packages/stock-core
      ├─ /api/analyze  → packages/stock-core
      ├─ /api/chat     → OpenCode SDK → stock-analyst
      └─ /api/artifacts → 会话级 HTML / JSON 策略报告

packages/stock-core（可复用量化内核）
  ├─ Tushare / Alpha Vantage 数据适配器
  ├─ 复权与统一 Bar 数据模型
  ├─ 技术指标
  └─ 双均线回测与绩效指标

.opencode/tool（OpenCode 聊天工具）
  ├─ 单标的工具复用 packages/stock-core
  └─ EPS 组合工具调用 Python 点时数据流水线并持久化审计报告
```

## 第一版能力

- `app-stock`：独立前端、独立 API、独立启动和部署脚本。
- `stock-core`：真实行情、标准化、技术分析和双均线回测。
- `stock-analyze`：区间收益、波动率、最大回撤、均线、RSI 与量比。
- `stock-backtest`：下一交易日开盘成交，模拟佣金、最低佣金、印花税、滑点和交易单位。
- `stock-analyst`：OpenCode 专用 Agent，只开放股票分析与回测工具。

## 第二阶段已完善

- 回测后自动输出“证据不足 / 结果脆弱 / 值得继续研究”三级结论，避免只展示漂亮收益数字。
- 将样本长度、完整交易次数、年化收益、相对基准超额、最大回撤和夏普拆成逐项检查。
- 自动测试快均线和慢均线的相邻参数组合，展示参数邻域中的年化、回撤和夏普。
- AI 对话携带可行性检查和参数敏感性摘要，使追问围绕当前实验数据展开。
- `app-cmcc` 登录后增加统一入口，并使用独立页面容器持久化股票产品状态。
- 统一 Alpha Vantage 复权 OHLC，修正北交所 920 代码识别，并对齐策略和基准的有效回测区间。
- 将参数稳定性纳入可行性初筛，防止单一参数点表现良好时直接给出积极评级。
- 保存每次成功回测的请求快照；参数变化后标记旧结果，AI 上下文同时区分草稿参数和已运行参数。
- 股票服务使用不透明会话句柄隔离 OpenCode session，并限制请求体、输入范围和行情并发。
- EPS 组合回测使用历史沪深300成分股与真实 `pubDate`，避免 WorkBuddy 示例中“当前成分静态回溯 + 一个月近似滞后”的两类偏差。
- 每次 EPS 回测输出完整 JSON、自包含 HTML 与逐项数据审计；即使模型工具调用后漏掉收尾文本，服务也会从已完成产物生成确定性摘要。
- westock 作为免费交叉校验源接入：只用 `BasicEPS` 自算 TTM 校验最近一期，不把缺少公告日的数据悄悄降级为历史信号。

## 判断策略是否“可行”的标准

不能只看一次回测的总收益。产品后续的策略验收应至少包含：

1. 数据不存在未来函数，使用当时可获得的信息。
2. 计入真实交易成本、滑点、停牌、涨跌停与容量限制。
3. 与买入持有及合适指数比较，不只看绝对收益。
4. 拆分训练、验证、样本外区间，并做滚动 walk-forward。
5. 检查参数邻域是否稳定，避免只在单一参数点表现突出。
6. 覆盖牛市、熊市、震荡市和极端行情。
7. 用最大回撤、夏普、换手、胜率、盈亏比和交易次数共同判断。

## 后续需求优先级

### P0：让结论可复现、可对比

1. 保存每次回测的参数、数据源、数据时间戳、代码版本、指标与交易明细。
2. 引入 Parquet + DuckDB 本地快照，避免同一次实验因上游数据修订而无法复现。
3. 增加实验列表、运行状态、失败原因、两次实验差异和结果导出。
4. 支持训练 / 验证 / 样本外区间和 walk-forward，把当前启发式结论升级为正式验收流程。

### P1：扩展策略和市场真实性

1. 抽象策略插件接口，逐步支持 RSI、动量、海龟、行业轮动和多因子选股。
2. 补充历史股票池、退市、ST、停牌、涨跌停、分红送转、成交容量和公告可用时间。
3. 支持多标的组合、仓位上限、再平衡、行业约束和更合适的基准体系。
4. 增加参数网格热力图、过拟合诊断、滚动收益和不同市场阶段切片。

### P2：从研究走向持续使用

1. 增加自选策略、研究笔记、报告分享和定时数据更新。
2. 接入 JQData / QMT / 券商行情，提高 A 股分钟级和历史成分数据完整度。
3. 在权限、审计、风控和人工确认完善后增加模拟盘；实盘交易保持为单独项目评估。

## 验收口径

- 任一回测都能说明数据源、复权方式、信号时间、成交时间、费用和基准。
- 美股 OHLC 使用一致复权比例，北交所 920 代码能够识别为 `.BJ`。
- 修改表单后旧结果必须显示过期状态，AI 不得把草稿参数当成该结果的实际参数。
- 相同数据快照与代码版本下重复运行，关键指标应一致。
- 页面不会把“历史表现好”描述为未来必然有效；证据不足时明确指出缺失项。
- `app-stock` 可以独立构建和运行，也能在 `app-cmcc` 登录后的 `/stock-lab` 路由完整使用。
- `app-cmcc` 与股票产品其中一方升级失败时，不应破坏另一方的构建和既有业务路由。

历史回测不代表未来表现，产品结果仅用于研究，不构成投资建议。
