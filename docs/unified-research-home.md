# 统一研究入口与案例集

## 行为

- 侧边栏保留“深度研究”，创建带 `researchMode` 的 `/new-session` 草稿，默认 `deep`。
- `quick` 使用原 LangGraph 创建/启动接口；`deep` 复用原 OpenCode 深度研究提交链路。
- `/general-deepinsight` 旧首页进入快速草稿；旧任务、案例链接及结果页保持可用。
- 研究首页不展示案例。快速仅上传文档；深度支持文件、图片和文件夹，并可选模型。
- 两套编辑器使用同一草稿数据和首页样式。快速输入不挂载 OpenCode 目录、模型及权限控件，
  避免在路由过渡期间被模型查询阻塞；深度适配器按需挂载，并在切换时保留模型选择。
- 模式仅决定新任务的引擎，不修改 `build/plan`，也不转换已有任务。

## 附件

同一草稿保留浏览器原文件以及两个来源的独立上传回执。只上传当前模式所需的文件，
再次切换复用回执，不将 OpenCode 路径作为 LangGraph 上传编号。
不支持的格式、文件夹、大小或重名会明确标记并阻止提交；失败保留草稿并支持重试。
深度提交仍发送原文件引用，不将 Word 正文塞进用户消息。

原件仅保留在内存中，不写入新的浏览器文件数据库。刷新后，已有回执仍可用于对应引擎；
若要切换到尚未上传的引擎，需要重新选择原文件。附件状态与异步结果按账号、工作区及草稿隔离。
删除操作只允许清理当前未提交草稿的附件；离开页面不会递归删除研究任务文件。

## 案例

统一列表请求 DockAPI 的 `sources=all` 聚合接口，分类仍为“通用深度研究”，
并显示“快速/深度”来源标签。打开和删除按 `source` 分流，加载状态按来源与编号区分。
两套原详情组件及快照结构不变。发布/删除会使聚合列表缓存失效。
“做同款”只带入问题和模式，不自动运行、不复制私有资料；其他专家团行为不变。

## 验证与发布

新增附件状态单测、统一首页及混合案例浏览器验收，并保留旧研究详情和通用对话回归。
性能基线使用生产构建，记录首页标题/输入框就绪、目录请求数、首次发送创建/提交次数。
具体本机测试日志存放在工作区 `.codex-artifacts/markdown-20261016/research-*`。

先更新 DockAPI 后端，再更新前端；不需要修改 LangGraph Python 服务或 OpenCode 模型执行核心。
本次不自动提交、推送、部署，不调用线上模型进行收费研究。

- 前端类型检查、生产构建通过；构建保留已有大体积 chunk / sourcemap 提示。
