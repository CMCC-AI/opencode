# Turn findings into research actions

Use this guide when planning reveals an input/output mismatch, or an existing review identifies a scientific gap. It adds no review stage, required file, schema, tool or release gate. Work within the current task, permissions and resource-policy. Use English benchmark artifacts.

## Start from the finding, not the audit form

Read the actual observation and its cited data. Restate the unanswered scientific question and identify the first missing dependency. A review that says passed does not cancel a concrete scientific omission in its body. Distinguish missing evidence, incorrect computation, weak comparison, unclear presentation and a valid negative finding; they require different actions. Public task descriptions of how inputs are intended to be used can reveal missing analysis even when the data are absent. Do not infer that absent data means the intended analysis is unnecessary. Unknown specifications stay unknown; do not infer exact cohort sizes or methods from task IDs, hidden evaluations or earlier benchmark answers.

Reuse the current plan or ordinary expert handoff. For the most consequential executable gap, write a short action paragraph containing: unanswered question; existing usable input; first concrete operation or targeted query; responsible specialist; expected scientific output; rough budget; and the next route if that operation fails. This is an execution instruction, not another review document. Perform the operation before another status-only update. Do not regenerate all ledgers or commission another reviewer to decide what to do when an existing finding already gives enough evidence. Update existing records after actual progress.

## Choose where to begin

| Finding | First operation | Next route and scientific deliverable |
|---|---|---|
| Missing external validation or recall | Inspect identifier columns in predictions/compositions and determine the independent truth labels needed. Search authorized references for the validation cohort, assay and identifier mapping. | Literature researcher returns verified source/download links plus join keys; engineer obtains a small real fragment and joins it to predictions. Report unmatched IDs before computing recall and its denominator. Then run the matched cohort; a toy optimizer check cannot replace this validation. |
| Missing baseline comparison | Recover the named method and version from public task/materials; identify its exact inputs and evaluation split. | Engineer independently implements the applicable baseline from its method specification, verifies representative examples, then executes matched full comparisons. Official code and outputs are not experiment dependencies. Do not substitute random/greedy controls for a required external method. |
| Missing entities or scale | Inspect actual grouping columns and count independent entities, observations and repeats separately. Trace the public data-generation path and its inputs/configuration. | Search source supplements, author repositories and data archives for missing entity-level inputs or reproducible generation. Run one genuine entity end to end before scaling. Resampling one entity does not create new entities. If raw inputs are absent, attempt their public recovery rather than inventing heterogeneity. |
| Missing model or inaccessible asset | Resolve the exact model/version and the first failing dependency or URL. | Use the existing resource-access assistance on that concrete failure. For allowed general dependencies or raw inputs, check compatible distributions and authorized caches; validate a representative real input. Target official assets remain reading-only. Preserve semantic version differences. |
| Existing data can answer the question but plot hides it | Compute the required relationship directly from source arrays and identify the independent unit for uncertainty. | Engineer redraws the relationship and groups; analyst checks values and interval definition. Pooling must not erase a required group. Choose CI, SD or quantiles for the scientific question and label them correctly; do not change methods merely to imitate a target image. |
| Contradictory result or empirical scaling | Recompute units, grouping, provenance and fit sensitivity on the same input. | Analyst compares defensible fit ranges/models and reports sensitivity plus raw points. Correct labels and conclusions; keep genuine disagreement. Do not force a published trend or select a favorable fit. |

## Search with a purpose

Derive queries from scientific method names, repository/package names, filenames, assay names and citations actually present in authorized inputs. For example combine the known method name with data availability, supplementary, code, validation cohort or benchmark labels. First use DOI/publisher data-availability sections, supplementary indexes and author README links; inspect their filenames and manifests for the missing dependency. Follow concrete citations and download paths instead of repeatedly searching a broad topic. Source-study identification is permitted via public scientific evidence, never via hidden task metadata. A search handoff should name the missing asset, identifiers, compatibility conditions and intended computation, not just request more literature. Never invent links, access success or execution logs.

Once a suitable candidate is found, hand its actual URL, revision, required files, key mapping and minimal command to an engineer in the next dispatch. Discovery specialists do not download by assertion. Engineers run the real operation; analysts turn the resulting outputs into the missing scientific result. If no candidate is found, broaden by the originating dataset/assay or cited cohort; if access fails, switch source/distribution with the existing access tool; if compatibility fails, diagnose identifiers/protocol rather than silently substituting data. Reuse evidence already collected.

## Spend effort on research

Use one concrete dependency probe at a time with a budget appropriate to remaining runtime; budget recovery together with the formal experiment so discovery does not consume all compute time. Continue useful independent research while a genuine dependency is blocked. Repeated identical failures need new evidence to justify another attempt. Stop a route on observed restrictions, incompatibility or budget limits and preserve what remains unanswered. State the next viable scientific route, rather than claiming global resource nonexistence.

Success means new usable evidence, a repaired computation, a matched comparison or a scientifically clearer result. A new plan, populated review fields or a stronger completion claim is not research progress. Keep existing audit implementation unchanged.
