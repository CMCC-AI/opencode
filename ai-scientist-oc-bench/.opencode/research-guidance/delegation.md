# File-based delegation and bounded chief context

The chief owns scientific scope, authorization, budget, routing and release decisions. Workers own assigned execution and detailed file delivery. Only the chief dispatches Task; workers always have task: deny. Follow task restrictions and benchmark/resource-policy.md (reference-only-v3); English benchmark artifacts, Chinese ordinary-run artifacts.

## Every assignment

Read the original INSTRUCTIONS.md, the assigned evidence files and relevant method profiles in the current workspace. Read Introduction.md when present. Sessions are fresh; do not assume previous worker memory. Do not search sibling workspaces, private local projects or hidden evaluation materials. Configuration templates and bundled guidance are allowed references, not scientific answers.

Work only on the assigned item/claim and budget. Save detailed output before returning. Chief supplies exact writable paths; if absent use outputs/ai-scientist-workspace/<run-id>/<agent-name>-<assignment-id>.* and return those paths. Keep complete scientific evidence, tables, proposals, code, commands, stdout/stderr and reviews in files; log exact execution status, provenance and unperformed work. Read large files by relevant sections, stream arrays locally and keep tool outputs bounded. Never truncate or discard original evidence merely to shorten conversation.

Only curator merges canonical ledger, global plan, manifest and recovery plan. Other workers save proposals/observations/reviews, not shared canonical state. Engineer/operator own implementation and execution; analyst owns assigned analysis; writer owns report prose. Independent reviewers may write only their review products and never modify evidence under review. The figure editor inspects actual images and requests corrections by the producer. edit permission does not expand bash/network permissions. Parallel assignments must have disjoint write sets.

## Final receipt (maximum 1200 English characters)

```text
status: succeeded | incomplete | blocked | failed
items/claims: D1 / C1
artifacts: relative paths to complete outputs and evidence
findings: at most three decisive observations or blockers
next: responsible owner and concrete next action
```

Do not append the manuscript, full YAML/JSON, code, raw arrays, logs or a second long narrative. Existing role output contracts define the complete content of the saved artifact, not the Task reply. Missing capability or writes must be reported honestly with a repair route to chief. A succeeded assignment does not imply completed science or passed independent review. No worker may grant itself final verification; curator must preserve authorship and failing verdicts.

## Resumption and recovery

Curator maintains the run orchestration-state.md as a short path index, current P0 dependency list, chief decisions, budgets and pending review versions. Resume from original instructions, this index and bounded receipts; read detailed files only for the assigned dependency. Scientific ledger and frozen contracts remain authoritative. Recovery sessions keep the same division of labor; no chief implementation fallback. This protocol reduces context growth but does not configure provider context limits or guarantee compaction.
